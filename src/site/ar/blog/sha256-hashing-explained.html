شرح SHA-256: كيف تعمل دوال التجزئة التشفيرية

أبريل 2026 قراءة 8 دقائق بقلم فريق Zecure

تُعد SHA-256 من أكثر الخوارزميات التشفيرية انتشارًا على الإنترنت، إذ تُستخدم في شهادات TLS وBitcoin وGit ومئات البروتوكولات الأمنية. وفهم طريقة عملها يساعدك على استخدامها بشكل صحيح وتجنّب الخطأ الشائع المتمثل في استخدامها في غير موضعها.

ما هي SHA-256؟

SHA-256 (اختصار Secure Hash Algorithm 256-bit، أي خوارزمية التجزئة الآمنة بطول 256 بت) عضو في عائلة SHA-2 من دوال التجزئة التشفيرية، نشرتها NSA واعتمدتها NIST معيارًا في عام 2001. تأخذ أي مُدخل، سواء كان حرفًا واحدًا أو ملفًا بحجم تيرابايت أو أي شيء بينهما، وتُنتج مُخرجًا ثابت الطول من 256 بت (32 بايت)، يُمثَّل بـ 64 حرفًا ست عشريًا.

أمثلة على مُخرجات SHA-256
المُدخل: "hello"
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
المُدخل: "Hello" (بحرف H كبير)
185f8db32921bd46d35cc2bc4b4d32d1a4568b07e3e2bc0b6c1e3804dda66a84
المُدخل: "" (سلسلة فارغة)
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

لاحظ أن تغيير حرف واحد فقط (h صغير مقابل H كبير) يُنتج قيمة تجزئة مختلفة تمامًا. يُسمّى هذا تأثير الانهيار الجليدي (avalanche effect)، وهو خاصية أساسية في دوال التجزئة الجيدة.

الخصائص الأربع لدالة التجزئة التشفيرية

يجب أن تحقق SHA-256 (وغيرها من دوال التجزئة التشفيرية) أربع خصائص أساسية:

  1. الحتمية: المُدخل نفسه يُنتج دائمًا المُخرج نفسه. فـ Hash("hello") هي دائمًا السلسلة نفسها المكوّنة من 64 حرفًا.
  2. مقاومة الصورة الأولية: إذا أُعطيت قيمة تجزئة، فمن غير الممكن حسابيًا إيجاد المُدخل الأصلي. لا يمكنك "عكس" قيمة تجزئة SHA-256.
  3. مقاومة الصورة الأولية الثانية: إذا أُعطيت مُدخلًا وقيمة تجزئته، فمن غير الممكن إيجاد مُدخل مختلف له قيمة التجزئة نفسها.
  4. مقاومة التصادم: من غير الممكن إيجاد أي مُدخلين مختلفين يُنتجان قيمة التجزئة نفسها.

كيف تعمل SHA-256 (بشكل مبسّط)

تعالج SHA-256 المُدخل على شكل كتل بحجم 512 بت (64 بايت). إليك نظرة عامة على الخوارزمية:

  1. الحشو (Padding): يُحشى المُدخل حتى يصبح طوله من مضاعفات 512 بت. يُضاف بت قيمته 1، تليه أصفار، ثم طول الرسالة الأصلية كعدد صحيح من 64 بت بترتيب big-endian.
  2. قيم التجزئة الابتدائية: تُهيَّأ ثماني كلمات بطول 32 بت بالأجزاء الكسرية من الجذور التربيعية لأول 8 أعداد أولية. هذه الثوابت معروفة للجميع وليست سرية.
  3. دالة الضغط: تُعالَج كل كتلة بحجم 512 بت عبر 64 جولة من عمليات الخلط، تشمل عمليات AND وOR وXOR على مستوى البت، والتدوير، والجمع مع 64 ثابتًا للجولات (مشتقة من الجذور التكعيبية لأول 64 عددًا أوليًا).
  4. المُخرج: بعد معالجة كل الكتل، تُضَم قيم التجزئة الثماني (كل منها 32 بت) معًا لتكوين الملخص (digest) بطول 256 بت.

صُممت العملية بأكملها بحيث يعتمد كل بت في المُخرج على كل بت في المُدخل، ما يجعل التنبؤ بها أو عكسها مستحيلًا.

SHA-256 مقابل SHA-1 مقابل SHA-512

SHA-1160 بت / 40 حرفًا ست عشريًا512 بت80 بتمكسورة (2017)
SHA-256256 بت / 64 حرفًا ست عشريًا512 بت128 بتآمنة
SHA-384384 بت / 96 حرفًا ست عشريًا1024 بت192 بتآمنة

في الواقع، SHA-512 أسرع من SHA-256 على معالجات 64 بت لأنها تُجري جولات أقل على كتل أكبر. ولمعظم التطبيقات، توفر SHA-256 أمانًا أكثر من كافٍ.

أين تُستخدم SHA-256 عمليًا

  • شهادات TLS/HTTPS: تستخدم التوقيعات الرقمية في شهادات X.509 خوارزمية SHA-256 (أو SHA-384) لتوقيع محتوى الشهادة.
  • Git: استخدم Git تاريخيًا SHA-1، لكنه ينتقل إلى SHA-256 لمعرّفات الـ commit والـ blob.
  • Bitcoin: يستخدم تعدين إثبات العمل (proof-of-work) في Bitcoin خوارزمية SHA-256 مرتين (SHA-256d) لتجزئة ترويسات الكتل.
  • HMAC-SHA256: تستخدم توقيعات JWT (HS256) وكثير من أنظمة مصادقة API خوارزمية HMAC مع SHA-256 لتوقيع الرسائل.
  • تخزين مفاتيح API: بدلًا من تخزين مفاتيح API كنص صريح، تخزّن التطبيقات قيمة تجزئة SHA-256 الخاصة بها. ومع كل طلب، يُجزَّأ المفتاح الوارد وتُقارن القيمتان.
  • سلامة الملفات: ينشر ناشرو البرمجيات مجاميع تحقق SHA-256 إلى جانب ملفات التنزيل ليتمكن المستخدمون من التأكد من أن الملفات لم يُعبث بها.

SHA-256 لمفاتيح API والرموز المميزة

عند بناء API، لا يجب أبدًا تخزين مفاتيح API كنص صريح. بدلًا من ذلك، خزّن قيمة تجزئة SHA-256 لكل مفتاح:

// Node.js: storing and verifying an API key
import crypto from 'crypto';

// When issuing a new key (show raw key to user once)
const rawKey = crypto.randomUUID();
const storedHash = crypto.createHash('sha256').update(rawKey).digest('hex');
// Store storedHash in database, show rawKey to user

// When verifying an incoming request
function verifyKey(incoming, storedHash) {
  const hash = crypto.createHash('sha256').update(incoming).digest('hex');
  // Use timingSafeEqual to prevent timing attacks
  return crypto.timingSafeEqual(Buffer.from(hash), Buffer.from(storedHash));
}

لا تستخدم SHA-256 أبدًا لتخزين كلمات المرور. يمكن لـ SHA-256 حساب نحو 10 مليارات قيمة تجزئة في الثانية على وحدة معالجة رسومات (GPU) حديثة. والمهاجم الذي يسرق قاعدة بياناتك يمكنه كسر كلمات المرور الشائعة في ثوانٍ. استخدم bcrypt أو Argon2id أو scrypt، فهي مصممة خصيصًا لتكون بطيئة وكثيفة الاستهلاك للذاكرة.

الفرق الحاسم: التجزئة العامة مقابل تجزئة كلمات المرور

هذه أهم فكرة في هذا المقال. SHA-256 دالة تجزئة تشفيرية للأغراض العامة، وهي مصممة لتكون سريعة. والسرعة ميزة في سلامة البيانات وHMAC والتوقيع، لكنها في تخزين كلمات المرور عدوّ، إذ يستطيع المهاجم تجربة مليارات التخمينات في الثانية.

أما خوارزميات تجزئة كلمات المرور مثل bcrypt وArgon2id وscrypt فهي بطيئة عمدًا وكثيفة الاستهلاك للذاكرة. وقد صُممت لتبقى مكلفة حسابيًا حتى مع تطور العتاد، عبر رفع معامل التكلفة.

استخدم SHA-256 لـ: سلامة الملفات، وتخزين مفاتيح API، والتوقيع بـ HMAC، والتوقيعات الرقمية، وإزالة البيانات المكررة.

توليد قيم تجزئة SHA-256

يمكنك حساب قيم تجزئة SHA-256 مباشرة داخل متصفحك باستخدام مولّد قيم التجزئة المجاني لدينا، دون إرسال أي بيانات إلى خادم. أو برمجيًا بلغة البرمجة التي تختارها:

// Python
import hashlib
digest = hashlib.sha256(b"hello world").hexdigest()

// Node.js
import crypto from 'crypto';
const digest = crypto.createHash('sha256').update('hello world').digest('hex');

// Go
import "crypto/sha256"
sum := sha256.Sum256([]byte("hello world"))
