مولّد مفاتيح AES-256 المجاني

أنشئ فورًا مفتاح تشفير AES عشوائيًا تشفيريًا بطول 256 بت (64 حرفًا ست عشريًا) — آمنًا للاستخدام في بيئة الإنتاج مع AES-GCM.

مفتاح AES-256 64 حرف hex
كل أنواع المفاتيح

ما هو مفتاح AES-256؟

مفتاح AES-256 هو 32 بايت (256 بت) من البيانات العشوائية تشفيريًا، يُستخدم مع خوارزمية التشفير المتماثل AES. وعند تمثيله بالنظام الست عشري يصبح 64 حرفًا (كل رقمين ست عشريين = 1 بايت). وهذا هو طول المفتاح الذي اعتمدته وكالة الأمن القومي الأمريكية (NSA) للمعلومات المصنّفة «سري للغاية»، وتستخدمه AWS وApple وSignal وكل اتصال HTTPS.

يجب أن يُولَّد المفتاح بواسطة CSPRNG (مولّد أرقام عشوائية آمن تشفيريًا) — وتستخدم هذه الأداة crypto.getRandomValues(new Uint8Array(32)) داخل متصفحك. أما المفتاح المشتق من كلمة مرور أو طابع زمني أو أي مصدر يمكن التنبؤ به فهو ضعيف تشفيريًا مهما كان عدد بتاته.

لم يُكسر AES-256 عمليًا قط. فالثغرات الوحيدة تكمن في المفتاح — توليد ضعيف، أو قيم مكتوبة مباشرة في الشيفرة، أو تخزين غير كافٍ. أما الخوارزمية نفسها فسليمة.

كيف تستخدم هذا المفتاح في Node.js

// Store key as hex in AES_KEY env variable, then:
import crypto from 'crypto';

function encrypt(plaintext) {
  const key = Buffer.from(process.env.AES_KEY, 'hex'); // 32 bytes
  const iv  = crypto.randomBytes(12);              // 96-bit IV for GCM
  const cipher = crypto.createCipheriv('aes-256-gcm', key, iv);
  const enc = Buffer.concat([cipher.update(plaintext), cipher.final()]);
  return { iv: iv.toString('hex'), data: enc.toString('hex'), tag: cipher.getAuthTag().toString('hex') };
}
  • استخدم دائمًا نمط AES-GCM — فهو يوفّر التشفير والمصادقة معًا
  • أنشئ متجه تهيئة (IV) عشوائيًا جديدًا لكل عملية تشفير (لا تُعِد استخدام IV أبدًا)
  • خزّن الـ IV ووسم المصادقة (auth tag) مع النص المشفّر — فهما ليسا سرّيين
  • أما المفتاح نفسه فيجب أن يبقى سرّيًا وأن يُستبدل عند اختراقه

الأسئلة الشائعة

مفتاح AES-256 هو 32 بايت (256 بت) من البيانات العشوائية، يُستخدم لتشفير البيانات وفك تشفيرها بخوارزمية AES. ويُكتب على شكل 64 حرفًا ست عشريًا (hex). ويُستخدم المفتاح نفسه للتشفير ولفك التشفير معًا (تشفير متماثل).

استخدم AES-GCM في التطبيقات الجديدة — فهو نمط تشفير مُصادَق (authenticated encryption) يوفّر السرية والتحقق من السلامة معًا. وتجنّب نمط ECB (لأن الأنماط الموجودة في النص الأصلي تتسرّب إلى النص المشفّر). أما AES-CBC فمقبول إذا اقترن بـ HMAC-SHA256، لكن استخدام GCM بشكل صحيح أسهل.

لا. تُولَّد المفاتيح باستخدام crypto.getRandomValues(new Uint8Array(32)) بالكامل داخل متصفحك، ولا تُرسل أي بيانات إلى أي مكان. افتح أدوات المطوّر (DevTools) ثم تبويب Network أثناء التوليد، ولن ترى أي طلب صادر.

في بيئة الإنتاج استخدم خدمة مخصّصة لإدارة المفاتيح: AWS KMS أو GCP Cloud KMS أو HashiCorp Vault. تتولّى هذه الخدمات تخزين المفاتيح وتدويرها وتسجيل عمليات التدقيق. وفي بيئة التطوير خزّن المفتاح كمتغيّر بيئة في ملف .env مستثنى من git (عبر gitignore). ولا تكتبه مباشرة في الشيفرة المصدرية أبدًا.
