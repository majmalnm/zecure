مفتاح API (UUID v4) RFC 4122
كل أنواع المفاتيح

ما هو مفتاح API بصيغة UUID v4؟

UUID (المعرّف الفريد العالمي، Universally Unique Identifier) في إصداره الرابع هو معرّف عشوائي بطول 128 بت بالصيغة xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx — أي 32 رقمًا ست عشريًا (hex) موزّعة على 5 مجموعات تفصل بينها شرطات. يشير الرقم 4 في المجموعة الثالثة إلى الإصدار 4 (العشوائي)، ويرمّز الموضع y بتات المتغيّر (variant).

UUID v4 هو الصيغة المعتادة لمفاتيح API لأنه يوفّر 122 بت من العشوائية (وهذا يكفي لمقاومة التصادم على أي نطاق واقعي)، ويسهل التعرّف عليه في كل مكان، ويعمل كرمز معتم (opaque token) لا يكشف شيئًا عن الجهة التي أصدرته ولا عن بنيته.

لا تستخدم لمفاتيح API إلا معرّفات UUID مولّدة عبر CSPRNG (مولّد أرقام عشوائية آمن تشفيريًا). مولّدات UUID المعتمدة على Math.random() يمكن التنبؤ بمخرجاتها. أما هذه الأداة فتستخدم crypto.getRandomValues() — مصدر الإنتروبيا نفسه الذي يستخدمه نظام تشغيلك.

كيف تستخدم مفتاح API في تطبيقك

1
انسخ أحد معرّفات UUID أعلاه وخزّنه كمتغيّر بيئة: API_KEY=xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx. لا تكتبه مباشرة في الشيفرة المصدرية أبدًا.
2
أرسله في ترويسة Authorization مع طلبات API: Authorization: Bearer <key> أو في ترويسة مخصّصة X-API-Key: <key>.
3
خزّنه بعد تجزئته في قاعدة بياناتك (SHA-256 مناسبة للبحث، وbcrypt للحالات الأعلى حساسية). واعرض المفتاح الخام للمستخدم مرة واحدة فقط عند إنشائه.
4
وفّر تدوير المفاتيح — اسمح للمستخدمين بإعادة توليد المفتاح دون أن يفقدوا الوصول إلى حساباتهم.
// Node.js — verify incoming API key
import crypto from 'crypto';

function verifyApiKey(incoming, storedHash) {
  const hash = crypto.createHash('sha256').update(incoming).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(hash), Buffer.from(storedHash));
}

الأسئلة الشائعة

UUID v4 معرّف بطول 128 بت، منها 122 بت عشوائية تشفيريًا. صيغته xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx. يشير «4» إلى الإصدار 4 (العشوائي)، ويرمّز «y» المتغيّر (variant). وهو الصيغة الأكثر شيوعًا لرموز API المعتمة (opaque tokens).

خزّن الـ UUID كمتغيّر بيئة في تطبيقك. وفي طلبات API أرسله في الترويسة Authorization: Bearer <uuid> أو في ترويسة مخصّصة X-API-Key. وعلى الخادم، احسب له قيمة تجزئة (hash) قبل تخزينه في قاعدة البيانات.

لا. تُولَّد معرّفات UUID باستخدام crypto.getRandomValues() بالكامل داخل متصفحك، ولا يوجد خادم. افتح أدوات المطوّر (DevTools) ثم تبويب Network أثناء التوليد، ولن ترى أي طلب صادر.

لا. خزّن المفاتيح في قاعدة البيانات بعد تجزئتها (SHA-256)، تمامًا مثل كلمات المرور، واعرض المفتاح الخام مرة واحدة فقط عند إنشائه. بهذه الطريقة لن تنكشف مفاتيح API النشطة حتى لو سُرّبت قاعدة البيانات كاملة. ووفّر إمكانية تدوير المفاتيح حتى يتمكّن المستخدمون من إبطال أي مفتاح مسرَّب.
