مولّد سرّ JWT مجاني

أنشئ سرّ توقيع آمنًا تشفيريًا لرموز JSON Web Tokens — مكوّنًا من 64 حرفًا عشوائيًا من base62، ومناسبًا لـ HS256 وHS384 وHS512.

ما هو سرّ JWT؟

سرّ JWT (رمز JSON Web Token) هو المفتاح المستخدم لإنشاء توقيع تشفيري يثبت أن الرمز لم يُعبث به. عندما يُصدر خادمك رمز JWT، فإنه يوقّع الترويسة (header) والحمولة (payload) بهذا السرّ باستخدام HMAC-SHA256 (HS256) أو أحد أشكالها الأقوى. وعندما يستقبل رمزًا، يعيد حساب التوقيع ويتحقق من تطابقه — فإن لم يتطابق رُفض الرمز.

أمان كل رمز JWT يُصدره تطبيقك يعتمد بالكامل على حماية هذا السرّ. فالسرّ المسرَّب أو الضعيف يتيح لأي شخص تزوير رموز صالحة وانتحال صفة أي مستخدم في نظامك.

لا تستخدم أبدًا سرّ JWT ضعيفًا أو قابلًا للقراءة. سلاسل مثل "secret" و"mysecretkey" أو أي كلمة أو عبارة يسهل تخمينها جدًا، وقد كانت وراء هجمات حقيقية لتزوير الرموز.

كيف تستخدم هذا السرّ

1
انسخ أحد الأسرار أعلاه وخزّنه كمتغيّر بيئة: JWT_SECRET=your-64-char-key. استخدم سرًّا مختلفًا لكل بيئة (التطوير، والاختبار staging، والإنتاج).
2
وقّع الرموز باستخدام مكتبة JWT وسرّك:
// Node.js with jsonwebtoken
import jwt from 'jsonwebtoken';

const token = jwt.sign(
  { userId: user.id, role: user.role },
  process.env.JWT_SECRET,
  { expiresIn: '15m', algorithm: 'HS256' }
);

// Verify (throws if invalid)
const payload = jwt.verify(token, process.env.JWT_SECRET);
3
لا تضف هذا السرّ أبدًا إلى نظام التحكم في الإصدارات. أضف .env إلى .gitignore وتحقق من ذلك بالأمر git check-ignore -v .env قبل أول push.
4
بدّله عند الاختراق — إذا تسرّب السرّ فأنشئ سرًّا جديدًا فورًا. ستصبح كل الرموز الحالية غير صالحة (وسيحتاج المستخدمون إلى تسجيل الدخول من جديد).

الأسئلة الشائعة

يجب أن يكون سرّ JWT المستخدم مع HS256/HS384/HS512 بطول 256 بت (32 بايت) على الأقل من البيانات العشوائية تشفيريًا. ينتج هذا المولّد 64 حرفًا عشوائيًا من base62 — أي نحو 381 بت من الإنتروبيا، وهذا أعلى بكثير من الحد الأدنى الذي تتطلبه أي خوارزمية.

لا. أنشئ دائمًا سرًّا مختلفًا لكل بيئة. فأسرار بيئة التطوير غالبًا ما تكون أكثر عرضة للانكشاف (تُشارَك مع أعضاء الفريق وتوجد في ملفات .env المحلية)، ويجب ألا يتمكّن أحد بسرّ تطوير مسرَّب من تزوير رموز الإنتاج. أنشئ أسرارًا منفصلة لبيئات التطوير والاختبار (staging) والإنتاج وخزّنها كلًّا على حدة.

تستخدم HS256 سرًّا مشتركًا (تشفير متماثل) — أي طرف يملك السرّ يستطيع توقيع الرموز والتحقق منها معًا. أما RS256 فتستخدم زوج مفاتيح خاص/عام (تشفير غير متماثل) — لا يستطيع التوقيع إلا مالك المفتاح الخاص، بينما يستطيع أي شخص لديه المفتاح العام التحقق. استخدم RS256 في معماريات الخدمات المصغّرة (microservices) حيث تتحقق عدة خدمات من الرموز بينما تُصدرها خدمة واحدة فقط.

خزّنه كمتغيّر بيئة يُحقن وقت التشغيل — وليس في الشيفرة المصدرية أبدًا. وفي بيئة الإنتاج استخدم مدير أسرار مثل AWS Secrets Manager أو GCP Secret Manager أو HashiCorp Vault. ولخطوط CI/CD استخدم مخزن الأسرار في منصتك (GitHub Actions Secrets وVercel Environment Variables وغيرها).
