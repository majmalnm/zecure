أداة ترميز Base64 وفك ترميزه مجانًا

رمّز أي نص أو بيانات إلى Base64، أو فك ترميز Base64 وأعده نصًا، بالوضعين القياسي والآمن للروابط، ودون أي اتصال بخادم.

ما Base64؟

Base64 نظام ترميز يحوّل البيانات الثنائية إلى نص، فيمثّلها في صورة سلسلة من أحرف ASCII القابلة للطباعة. يحوّل كل 3 بايتات من المدخل إلى 4 أحرف من أبجدية من 64 حرفًا: A–Z وa–z و0–9 و+ و/. وتُضاف أحرف حشو (=) في النهاية إذا لم يكن المدخل من مضاعفات 3 بايتات.

تكون النتيجة أكبر من المدخل بنحو 33%، لكن يمكن نقلها بأمان عبر أي قناة تتعامل مع نص ASCII، بما في ذلك نصوص رسائل البريد الإلكتروني وحمولات JSON وترويسات HTTP وسمات HTML.

متى يستخدم المطوّرون Base64؟

  • HTTP Basic Auth: تُرمَّز بيانات الدخول بـ Base64 بالصيغة username:password قبل وضعها في الترويسة Authorization: Basic.
  • JSON Web Tokens (JWT): تُرمَّز ترويسات JWT وحمولاتها بـ Base64 الآمن للروابط (Base64url)، ما يجعلها آمنة في سلاسل الاستعلام في الروابط دون ترميز النسبة المئوية (percent-encoding).
  • تضمين الصور أو الخطوط في CSS/HTML: تستخدم روابط Data URI ترميز Base64 لتضمين الملفات الثنائية مباشرة: src="data:image/png;base64,..."
  • مرفقات البريد الإلكتروني (MIME): تُرمَّز المرفقات الثنائية مثل الصور أو ملفات PDF بـ Base64 قبل تضمينها في نص الرسالة.
  • تخزين البيانات الثنائية في JSON: لا يحتوي JSON على نوع بيانات ثنائي، لذا تُرمَّز الكتل الثنائية (المفاتيح، التواقيع، الشهادات) بـ Base64 أولًا.

Base64 ليس تشفيرًا. يستطيع أي شخص فك ترميز سلسلة Base64 فورًا، فلا يوجد مفتاح ولا سرّ. لا تعتمد أبدًا على Base64 لحماية البيانات الحساسة، واستخدم تشفيرًا حقيقيًا (AES-256-GCM) للمعلومات السرية.

Base64 القياسي مقابل الآمن للروابط

يستخدم Base64 القياسي + و/ حرفين رقم 62 و63. وهذان حرفان خاصان في الروابط، فـ + يعني مسافة، و/ فاصل مسارات، ما يسبب مشكلات عندما تظهر سلاسل Base64 في الروابط.

يحل Base64 الآمن للروابط (ويُسمى أيضًا Base64url) هذه المشكلة باستبدال + بـ - و/ بـ _. وغالبًا ما يُحذف حشو = أيضًا. ويُستخدم هذا النوع في JWT وواجهات Google API ومعظم بروتوكولات المصادقة الحديثة على الويب.

// JavaScript: encode to URL-safe Base64
function toBase64Url(str) {
  return btoa(str)
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=+$/, '');
}

الأسئلة الشائعة

يحوّل ترميز Base64 البيانات الثنائية إلى نص ASCII باستخدام 64 حرفًا قابلًا للطباعة. فهو يرمّز كل 3 بايتات من المدخل في 4 أحرف، فيصبح المخرج أكبر بنحو 33%. ويُستخدم على نطاق واسع لتمرير البيانات الثنائية بأمان عبر قنوات لا تقبل إلا النص، مثل البريد الإلكتروني وJSON وترويسات HTTP.

لا. Base64 ترميز وليس تشفيرًا، ويمكن عكسه دون أي مفتاح. أي شخص يرى سلسلة Base64 يستطيع فك ترميزها فورًا. إذا كنت تحتاج إلى حماية البيانات، فاستخدم تشفيرًا حقيقيًا مثل AES-256. فـ Base64 يغيّر طريقة تمثيل البيانات فقط، ولا يخفيها.

يستبدل Base64 الآمن للروابط (Base64url) الحرف + بالحرف - والحرف / بالحرف _، فيزيل الأحرف التي لها معنى خاص في الروابط. وغالبًا ما يُحذف حشو (=) أيضًا. ويُستخدم هذا النوع في JWT ورموز OAuth ومعظم أنظمة المصادقة الحديثة على الويب.

يرمّز Base64 كل 3 بايتات معًا وينتج 4 أحرف. إذا لم يكن طول المدخل من مضاعفات 3، تُضاف أحرف حشو (=): علامة = واحدة لبايت واحد متبقٍّ، وعلامتا = لبايتين متبقيين. ويضمن هذا الحشو أن يعرف مفكّك الترميز أين تنتهي البيانات.
